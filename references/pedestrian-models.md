# Pedestrians, levels and elevators

## Choose and verify one route

**Official.** Start with `PedSource → PedGoTo → PedSink`. Place the source and reachable destination on the same Level. `PedGoTo` searches within the pedestrian's current level. A `TargetLine` can serve as a source or goal and belongs to its assigned level. Assign a custom agent class when the model needs per-person state such as origin, destination, boarding time or route choice. A native source creates individuals. Configure a built-in block with those individuals rather than moving their icons as a substitute for movement. [PedSource](https://anylogic.help/library-reference-guides/pedestrian-library/pedsource.html), [PedGoTo](https://anylogic.help/library-reference-guides/pedestrian-library/pedgoto.html), [Pedestrian Library blocks](https://anylogic.help/library-reference-guides/pedestrian-library/blocks.html).

- Create genuine Levels with distinct elevations. Use one consistent diagram scale and give doorway and landing coordinates room for pedestrian steering. A presentation rectangle shows a corridor or lobby. A native Wall constrains the walking space.
- Confirm every wall's segment geometry and keep lines inside reachable space. In the older ALP Wall representation examined locally, each curve anchor is followed by incoming and outgoing control points. For a straight rectangular perimeter use four anchor triples with collinear edge controls, `Closed=true`, and empty interior fill. Target lines use their own point schema.
- For stair modeling, the official example uses an inclined area or node for physical traversal. For two logical levels align the source exit line and target entry line at the transition, use `PedChangeLevel`, then route to the upper target. An inclined surface alone may change height without changing logical level. [Modeling stairs](https://anylogic.help/library-reference-guides/pedestrian-library/stairs.html), [PedChangeLevel](https://anylogic.help/library-reference-guides/pedestrian-library/pedchangelevel.html).

## Elevator and bank topology

**Official.** Place one Elevator markup element per actual car, with capacity, front/rear opening configuration, served levels, speed or time per level, and minimum stay. An automatic `PedElevator` binds one car expression and one target-level expression. It handles walking to the car, waiting, boarding and changing levels. Route the next `PedGoTo` to a target on the destination level. A destination equal to the current level bypasses the ride. The car's built-in automatic logic services calls by direction. [Elevator markup and automatic control](https://www.anylogic.help/markup/elevator.html), [PedElevator](https://www.anylogic.help/library-reference-guides/pedestrian-library/pedelevator.html).

- Use explicit served levels if there are presentation-only Levels or excluded floors. For base-floor presentation Z versus live cabin height, `getCabinZ()` is available in the installed 8.9.10 API. Check which view is active and verify floor visibility changes separately from movement.
- Use minimum stay as a combined stop allowance when that meets the spec. The public Elevator elements consulted expose minimum stay and door configuration. Separate opening/closing timing was not verified as independently configurable on the native element and should not be promised from a single stay value.
- To extend one car, duplicate the complete car/flow pair and connect both ports for each lane. The labs send an independent arrival stream to each car. An alternative is one source and a deterministic or random assignment before `PedElevator`, with one assignment stored per person. A shared lobby or a closest-car policy requires explicit assignment and testing. Separate automatic cars do not share dispatch.
- Test up and down trips, all served floors, boarding at full capacity, unfinished work at the stop time, and the final walk to a sink. If passengers are grouped, check the library's whole-group boarding behavior before interpreting wait and capacity.
- For a two-or-more-agent floor layout follow the separate-floor example. Its explicit served-level references cross agent ownership. Avoid replacing them with coincident coordinates.

## Local precursors

**Inspected on Windows PLE 8.9.10.** `Subway Entrance Hall - Phase 1` has a compact source, walk and sink route. `Pedestrian Elevator` shows level presentation, a custom pedestrian agent and automatic transfer. `Elevator Connecting Floors Defined by Different Agents` shows explicit cross-agent references. `Elevator Manual Control` and `Elevator Failure` cover optional control and interruption. `Stairs` is the stair markup reference. These examples are located with the inventory script. The separate multi-car `Elevator Group` demonstration in the AnyLogic gallery relies on a custom reusable block and is an optional reference.
